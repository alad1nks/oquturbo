### Вариант A · три раздела

Сегодня: дневной план, следующее упражнение, краткая обратная связь.

Игры: полный каталог и свободная игра.

Прогресс: история, сравнения, ритм, недельный обзор и личные достижения.

Настройки доступны из шапки каждого корневого раздела; профиль вложен в Прогресс.

### Вариант B · два раздела

Занятия: дневной план и каталог на одной странице, каталог ниже плана; ссылка «Выбрать игру» прокручивает к нему.

Мой прогресс: статистика и профиль с раскрытием подробностей.

Настройки доступны из шапок. Все функции те же, отличается группировка.

### Сравнение по трём заданиям

T1: A и B — один переход к Ready из стартового раздела; B конкурирует за место с каталогом.

T2: A — Игры → игра → режим/Ready; B — прокрутка или ссылка «Выбрать игру» → игра → режим/Ready. В A каталог имеет постоянный адрес.

T3: оба дают прямой вход в прогресс; A отделяет личное оформление от анализа, B требует особенно аккуратного раскрытия профиля.

Это оценка структуры, не измерение времени или успешности.

### Выбор A · D-006 / working

Три независимых намерения получают три устойчивых адреса. Дневной и свободный контексты различимы до старта. Профиль сохраняется, но не занимает четвёртый корневой раздел. Цена: достижения/персонализация на один уровень глубже; компенсируем явным пунктом «Профиль и достижения» в Прогрессе. B остаётся альтернативой, если проверка покажет лишние переключения. ## Карта разделов и переходов

Схема владения функциями • названия рабочие, RU

### Корень приложения

Первое открытие → Сегодня.

Корневая навигация: Сегодня ↔ Игры ↔ Прогресс.

Из шапки каждого раздела → Настройки → назад к вызывавшему разделу.

В Ready, игре, результате и вложенных деталях корневая навигация скрыта; явный выход возвращает к источнику.

### Сегодня → дневное занятие

План → следующее незавершённое упражнение → Ready → игра → результат.

Ниже цели: «Ещё раз» → Ready того же пункта; «К плану» → Сегодня.

Цель достигнута и запись подтверждена: «Следующее упражнение» → Ready следующего пункта.

Последний пункт: «Завершить занятие» → итог плана → Сегодня или Прогресс.

Продолжение не создаёт стек прошлых упражнений.

### Игры → свободная игра

Каталог → Number Sprint / Wide Eye / Don’t Tap / Memory Grid → меню режима → Ready.

Number Sprint → Custom → настройка → Ready с выбранной конфигурацией.

Word Flow / Dual Focus / Rotation Match / Number Trail / Symbol Count / Rule Switch → непосредственно Ready.

Результат → «Ещё раз» или «К режимам»; для игр без меню — «К играм». Свободная игра не завершает пункт плана.

### Прогресс → подробности

Обзор → период / день / история → игра → режим → серия (конфигурация).

Обзор → Ритм и обзор недели → сравнение серии / фокус недели.

Обзор → Профиль и достижения → имя/аватар, ранги, достижения, титулы, оформление, открытия.

Сегодня показывает краткий ритм/личный результат и ссылки на эти же подробности; отдельного второго обзора нет.

### Результат → прогресс → возврат

Предлагаемое вторичное действие «Статистика режима» открывает подробности той же игры/режима/конфигурации, период 30 дней с явной подписью.

Назад → тот же результат без повтора записи или запуска. В дневном контексте сохраняются цель и дальнейшее действие.

Если точную Custom-серию нельзя передать текущим маршрутом, необходим отдельный handoff на маршрутизацию; молча открывать другую серию нельзя.

## Возврат и сохранение контекста

Контракт предлагаемого поведения • runtime не проверен

### Дневная сессия

Ready/игра/результат → «К плану» и системный back → Сегодня. Незавершённая попытка не записывается как завершённая. Уже записанный результат и зачёт не отменяются выходом. Продолжить план запускает следующую незавершённую запись с Ready, а не восстанавливает стимул/таймер.

### Свободная сессия

Ready/игра/результат → «К режимам» (если меню есть), иначе «К играм». Custom-повтор использует ту же конфигурацию; меню возвращает выбранные значения в пределах текущего стека. Выход из меню → прежняя позиция каталога. Отмена Custom → меню, без старта сессии.

### Сохранение результата

Факт кода Number Sprint: зачёт происходит в ViewModel при сохранении завершённой попытки, до нажатия продолжения. «Следующее упражнение» лишь навигация. До подтверждения записи действие недоступно; при проблеме не показывать ложный успех. Для других игр проверить их собственные механизмы в 08, не копировать предположения.

### Вложенные страницы и настройки

День → игра → режим: назад по стеку, с прежними периодом, выбранным днём/серией и прокруткой. Из результата в статистику — назад к результату. Из Сегодня в недельный обзор — назад к Сегодня; из Прогресса — к Прогрессу. Настройки/профиль возвращают к месту входа; закрытие диалога языка — к настройкам.

### Корневые разделы и перезапуск

Переключение раздела сохраняет его список/выбор в живом стеке, повторное нажатие не дублирует маршрут. На корне системный back следует поведению платформы, без цикла вкладок. После закрытия процесса гарантируем только сохранённые данные: план текущего UTC-дня, результаты, профиль, настройки; активную попытку и прежний экран не обещаем.

### Смена UTC-дня и недоступные данные

Перед стартом/продолжением перечитать текущий план. Старый entryId не засчитывает новый пункт. Если день сменился, вернуться к Сегодня с актуальным планом; не показывать ложный итог нового дня. Ошибка вторичного блока не блокирует старт готового плана. Retry сохраняет выбранный контекст и повторяет только нужную загрузку.

### Контекст для handoff

Держать различимыми: источник (план/каталог), точную серию (игра, режим, конфигурация/язык где применимо), trainingEntryId/цель, факт сохранения результата, вызывающий экран и его выбор. Это логический контракт; новые аргументы маршрутов и форматы хранилища в этой задаче не вводятся.
