## Свидетельства текущего поведения

Проверены `feature/games/.../ui/GamesUiState.kt`, `model/TrainingGame.kt`,
`feature/remembernumbermenu/.../ui/RememberNumberMenuCustomOptionsDialog.kt`,
`RememberNumberMenuUiState.kt`, `RememberNumberMenuViewModel.kt`,
`feature/remembernumber/.../ui/RememberNumberViewModel.kt` и RU/EN/KK ресурсы.
Это чтение кода, не запуск приложения.

- Каталог: Number Sprint — 3 режима; Wide Eye — 4; Don't Tap — 7; Memory Grid — 3.
  Word Flow, Dual Focus, Rotation Match, Number Trail, Symbol Count, Rule Switch — по одному,
  с прямым переходом в Ready. Новых игр и меню нет.
- Custom defaults: длина 4, все десять цифр. Slider ограничивает длину 2–10, шаг 1.
  Реальная UI-валидация выбора: `count { it } >= 2`; ноль и одна цифра недопустимы.
  Ввод произвольного числа, ошибки формата и сетевые ошибки для этой формы не добавлены.
- Закрытие формы меняет только `show`; выбранные значения сохраняются в текущем ViewModel.
  Это не обещание восстановления после завершения процесса.
- `sessionMode()` нормализует набор цифр и определяет серию по конфигурации:
  `4 + 0123456789 → Classic`, `4 + 01 → Binary`, иначе
  `Custom / length:N;digits:S`. Поэтому «4 / 01» нельзя показывать отдельной Custom-серией.
  Демонстрационная независимая Custom-серия — «4 / 02».
- Свободный запуск не завершает пункт дневного плана; storage keys, IDs и маршруты не меняются.

## Композиция и взаимодействие

GameItem — одна интерактивная карточка: название, краткое действие игры, навыки обычным текстом,
явный переход и количество режимов, когда выбор существует. Высота растёт по содержимому.
В компактном варианте различение опирается на названия и описания; отдельные декоративные иконки
не добавлены. Поиск и фильтры не обоснованы текущим объёмом каталога и не вводятся.

ModeItem использует тот же принцип. Классический обозначен как простой вход без настройки;
Custom назван «Свой набор». Пример «увидели → запомнили → ввели» не содержит активного стимула.

Custom перенесён из диалога на отдельный прокручиваемый экран — **предложенное изменение UI**.
Порядок: доступные цифры → локальная ошибка → длина → подпись серии → действие → отмена.
Выбор показан галочкой, ошибка — текстом, а не только цветом. На 320/150% цифры идут в три колонки.
Длина остаётся ограниченным slider, клавиатурный ввод нового формата не добавляется.
Отмена/назад возвращают к режимам без запуска; повторное открытие сохраняет значения в текущем стеке.
Назад из меню возвращает прежнее место каталога. Реальное сохранение scroll position проверить в приложении.

Кнопка «К упражнению» обозначает переход в Ready, а не немедленный показ числа.
Все предложенные строки и изменения композиции требуют реализации отдельно; текущий Kotlin UI не изменён.

## Прототип и его границы

- C01 → C02 → C03 → C06; возвраты к настройкам/режимам/каталогу.
- C03: убрать 2 → C04; C04: добавить 2 → C03, убрать 0 → C05; C05: добавить 0 → C04.
  Disabled CTA C04/C05 не активируется.
- C07 — отдельный first-use flow start; продолжение ведёт к границе Classic.
- Все карточки каталога имеют переход на соответствующую явно подписанную границу маршрута
  с возвратом. Они не выдают неподготовленное поле за готовую игру.
- В H13 задачи 06 добавлена кнопка «Открыть каталог · прототип 07».
  Между страницами 06/07 используются URL-ссылки прототипа, открывающиеся отдельно;
  это мост между материалами, а не доказательство единого back stack.
- Settings и Progress используют существующие границы 06; Сегодня возвращает к completed Home.

Это сценарный прототип: не моделируются все комбинации десяти цифр, drag slider и произвольные
значения длины. Slider показывает 4 с реальным диапазоном 2–10. Граничные длины, keyboard control,
повторное открытие, системный back и независимость рекордов проверять при реализации.
Игровой цикл и Ready относятся к задаче 08. Неактивные сценарные контролы вне описанного пути
не следует интерпретировать как продуктовую блокировку этих цифр.
