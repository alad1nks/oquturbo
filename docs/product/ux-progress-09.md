| Показатель | Источник / вычисление / отсутствие данных |
| --- | --- |
| Попытки за 7 / 30 дней | `observeSessions()`, фильтр по `completedEpochDay` от today−6 / today−29 до today включительно. Только сохранённые завершённые попытки. |
| Время периода | Сумма `durationMillis` выбранных попыток. Предложена точность мин/с; текущий summary округляет вниз до целых минут. Для положительного времени <1 с писать «менее секунды», не ноль. |
| Правильные ответы / XP периода | Сумма `correctAnswers`; XP равен ей, не сумме score. |
| Итоги за всё время | `observeTotals()`: sessionCount, durationMillis, correctAnswers; для серии — точная запись в totals.series. Не пересчитывать all-time по усечённому журналу. |
| Рекорд | `observeRecords()` для точного ключа. У `GameRecord` нет даты. «Дата неизвестна» при отсутствии подтверждающей попытки; не искать дату по совпавшему score. |
| «Новый рекорд» в истории | `GameSession.isNewRecord`: факт на момент записи, не обещание, что он остаётся лучшим сейчас. Текущий рекорд подписать отдельно. |
| Лучший в периоде | max(score) выбранных записей; при пустом списке null/«Нет данных», не 0. |
| График | score по хронологически упорядоченным попыткам одной серии. X — порядковый номер попытки, Y — очки. Номер не изображает равные интервалы времени. |
| Точка / текст | Для каждой попытки: дата, время UTC в деталях, score и точная серия. Ноль рисуется на базовой линии; отсутствие записи вообще не создаёт точку. |
| Дни занятий / выполненного плана | `observePracticeHistory()` и `observeCompletionHistory()` → `calculatePracticeRhythm()`. Два независимых показателя. Не выводить план из факта игры. |
| Неизвестные дни | До trackingStartedEpochDay — «Нет данных»; после начала отслеживания отсутствие факта — «Не записано». Текущая серия с неясной границей обозначается как нижняя оценка, не точная длина. |
| Недельное сравнение | Отдельное окно 28 дней, последние 10 попыток последней точной серии: медиана предыдущих 5 / последних 5, абсолютная разница очков. До 10 — число имеющихся и недостаток истории. |

График не должен молча ограничиваться пятью `RecentActivity`: это лимит текущего превью истории,
не всего журнала. При реализации список/график должны позволять открыть все доступные значения,
без новой обязанности хранить больше 1000 попыток. Если totals.sessionCount > journal.size,
показывать «История ограничена последними сохранёнными попытками»; для периодов, затрагивающих
возможную усечённую часть, писать «В доступном журнале», не обещать полный итог периода.
`AllTime` не расширяет график до вымышленных старых дат. Его календарь в текущем коде — 28 дней;
в новом дизайне нужен явный заголовок этого окна, независимо от накопленного итога.

Новый пользователь определяется только после успешной загрузки: текущий критерий
`totals.sessionCount == 0 && records.isEmpty()`; ненулевой перенесённый XP следует показать
отдельно, не стирать из-за этого критерия. Loading и ошибка не интерпретируются как новичок.
При загрузке/ошибке одного источника готовые независимые данные остаются доступны;
состояния и повтор должны использовать 05 InlineFeedback/LoadingState. Восстановление
ошибки хранения не обещается без реального API. Эти состояния описаны контрактом,
но отдельный интерактивный сценарий отказа не моделировался.

## Точная идентичность и ограничения текущих моделей

Ключ: game + mode + variantId. Number Sprint уже нормализует 4 / 0123456789 в Classic,
4 / 01 в Binary; остальные Custom имеют `length:N;digits:S`. Не нормализовать повторно
и не объединять null с известной конфигурацией. Нераспознанную конфигурацию показывать
как «Настройки неизвестны», без сравнения с известными вариантами. Word Flow сохраняет
языковую variantId; языки не объединяются. Отсутствующие в fixture игры не удаляются из продукта.

`ModeTrend.scores` теряет даты; `RecentActivity` теряет время и правильные ответы;
`StatsDetailUiState` не несёт выбранную variantId. Поэтому график/детали требуют UI-проекций
из GameSession и явного сохранения точного ключа в состоянии/маршруте. Это handoff на
отдельную реализацию, не утверждение, что нынешняя модель уже поддерживает макет.
GameSession не содержит стабильный sessionId и признак запуска из плана. Детали не приписывают
источник запуска; текст о незавершённом плане приходит из отдельной истории.
Идентификатор для выбора попытки должен быть временным ключом снимка с учётом одинаковых
timestamps; изменение persisted ID или формата не входит в эту задачу.

Текущая Stats сравнивает средние соседних 7/30-дневных окон при ≥3 попытках с обеих сторон
и предыдущем среднем >0. Это другой расчёт, чем недельный обзор 5+5 за 28 дней. Если сохранять
его в деталях, подписывать окна, средние, выборки и «изменение среднего счёта», не «улучшение
навыка». В этой задаче процент не вынесен в главный вывод и не заменён выдуманной метрикой.
