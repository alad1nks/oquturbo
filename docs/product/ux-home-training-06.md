## Источники поведения

Проверены `feature/home/.../ui/HomeUiState.kt`, `HomeViewModel.kt`,
`HomeScreen.kt`, `PracticeRhythmCard.kt`, `TrainingFocusStatus.kt`,
`core/data/.../model/WeeklyFocus.kt`, `ProgressComparison.kt`.
Ограничения дневного зачёта и игр взяты из проверенного handoff 03 и PRODUCT.md.

- План, личный результат, ритм и недельный фокус имеют отдельные состояния.
  Уже существуют retryDailyTraining, retryPersonalResult и retryPracticeHistory.
- isStartingTraining отделяет запуск от готового плана; повторный запуск во время него недоступен.
- nextItem — первый невыполненный пункт. Продолжение открывает новое упражнение;
  незавершённая игровая попытка не обещается восстановленной.
- Полное занятие засчитано после сохранения последнего зачёта, не после нажатия CTA Главной.
- Личный результат сравнивает медианы двух групп по 5 попыток одной серии.
  Недостаток данных и отсутствие попыток не равны нулевому результату.
- Ритм, обзор недели и недельный фокус — существующие возможности. Их доступ сохранён
  по архитектуре 02; подробные экраны относятся к задаче 09.

Это чтение кода, не runtime-проверка. Демонстрационный план из 03:
Числовой спринт / Классический / цель 5; Широкий взгляд / Символы / цель 5;
Не нажимай / Категории / цель 8. Порядок — fixture, не новый генератор.

## Прототип и границы

Пять flow starts: начало, продолжение, ошибка плана, локальный повтор, 320/150%.
Проверенный граф:

- H01 → H10 → H17; «К плану» → H01; «Демо: первое упражнение зачтено» → H02.
- H02 → H18; «К плану» → H02; «Демо: весь план зачтён» → H03.
- H01 ↔ H09, H02 ↔ H16: раскрытие сохраняет соответствующий fixture прогресса.
- H06 → H11 → H01: повтор загрузки плана.
- H08 → H07 → H04: локальный повтор, готовый старт сохраняется.
- H03 → Игры; ссылки ритма, Прогресса и настроек ведут на обратимые границы своих задач.

[H17](https://www.figma.com/design/kElntn3nRWIQuFjyxUJNBM?node-id=49-418) и
[H18](https://www.figma.com/design/kElntn3nRWIQuFjyxUJNBM?node-id=49-453)
явно подписаны как сценарные стенды задачи 08. Из них открывается существующий игровой
прототип 03 в отдельной вкладке. Это не единый законченный цветной игровой прототип:
03 сохраняет собственные экраны возврата, а возврат в 06 моделируется стендами H17/H18.
Они не становятся продуктовым UI и не доказывают зачёт или сохранение.
Автопереход 1,2 с на loading frames — только имитация успешного ответа,
не обещание времени и не продуктовый timeout. Сбой может повториться в приложении;
retry не ограничен одним успешным исходом.
