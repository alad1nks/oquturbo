## Доступность и структурные результаты

На активных страницах (архив каталога исключён) проверены соответственно
146 / 153 / 151 / 108 / 170 узлов с reactions для 06 / 07 / 08 / 09 / 10.
Нет отсутствующих целей NODE и внутренних URL по разрешению ID; нет текстов шире
непосредственного родителя. Отдельная проверка активных целей пяти страниц не нашла
размеров меньше проектного ориентира 48×48. Это не проверка перекрытия/доступности касания
в runtime. Отсутствие переполнения по ширине само по себе не доказывает отсутствие клиппинга;
для выбранных состояний использованы renders и полное содержимое.

У узлов с реакциями есть текстовый потомок; это лишь проверка наличия подписи, а не
accessible name. Для клеток Memory Grid при реализации нужны координаты и состояние,
для выбранных языков/вкладок — selected, для раскрытия — expanded; декоративную графику
нельзя читать как текущий игровой стимул. Порядок озвучивания, live-region результата,
роль/имя кнопок, возврат фокуса и управление клавиатурой требуют приложения.

Focus у Button представлен отдельным прямоугольником: 2 px, offset 4 px, переменная
color/focus. Проверены его слои и render; пустой strokes у корня кнопки не означает
отсутствия рамки. В нижней панели focus отличается от selected и pressed.

Расчёт относительной яркости sRGB после разрешения aliases Foundations Light/Dark:

| Пара | Light | Dark |
| --- | --- | --- |
| text / catalog background | 13,74:1 | 15,84:1 |
| secondary text / background | 6,03:1 | 10,09:1 |
| action или focus / background | 5,99:1 | 10,08:1 |
| error / background | 6,61:1 | 10,27:1 |
| on-action / action | 6,50:1 | 8,54:1 |
| border / surface | 4,51:1 | 5,81:1 |

Проверены также эти текстовые роли на surface: минимум 6,50:1 в Light и 8,45:1 в Dark.
Это расчёт непрозрачных semantic-пар, не заявление о полной accessibility-compliance:
все декоративные сочетания, alpha-compositing, disabled, системные элементы и реальные
дисплеи не охвачены.
